## 3. 検証手順

### 3.0 事前準備

1. Pixel 8a に本アプリをインストール（`README.md` の「ビルドとインストール」参照）
2. モバイルICOCA アプリをインストールし、セットアップを完了させておく
3. **検証前にICOCA残高を 3,000円以上にしておく**（誤発火を避けるため）
4. 本アプリの設定で「自動監視」を **OFF** にしておく（検証中の意図しない発火を防止）

### 3.1 検証1 — ICOCA アプリの検出と Intent 起動（§28-3）

**アプリ内で完結する手順:**

1. 本アプリ → `Debug` タブを開く
2. 「ICOCAアプリ検出」が `検出: jp.co.westjr.android.icocaapp v____` になっていることを確認
   - `未検出` の場合、`AndroidManifest.xml` の `<queries>` 宣言が効いていない可能性
3. 「ICOCAアプリを起動」ボタンを押す → ICOCA アプリが前面に来ることを確認

**記入欄**

```
ICOCAアプリ検出        : [ ] 成功  [ ] 失敗
検出されたバージョン    :
launchIntent 起動      : [ ] 成功  [ ] 失敗
起動にかかった時間      :      ms
備考                   :
```

### 3.2 検証2 — 公開 Intent / Deep Link の列挙（§28-4）

**アプリ内で完結する手順:**

1. `Debug` タブ → 「ICOCAアプリ調査」→「exported コンポーネントを列挙」を押す
2. 表示された Activity 一覧と、対応する Intent フィルタ（action / scheme / host）を控える
3. 「共有」ボタンでテキストとして書き出し、下の記入欄に貼る

**adb を使う場合（任意・より詳細）:**

```bash
# 端末をUSB接続し、開発者オプション > USBデバッグ を有効にしておく
adb shell dumpsys package jp.co.westjr.android.icocaapp | sed -n '/Activity Resolver Table/,/Service Resolver Table/p'

# URLスキームを持つコンポーネントの確認
adb shell dumpsys package jp.co.westjr.android.icocaapp | grep -i -E 'scheme|android.intent.action.VIEW|exported'
```

> **注意**: ここで `exported=false` の内部 Activity が見えても、**直接起動してはならない**。
> 本アプリは `exported=true` かつ intent-filter が公開されているコンポーネントしか対象にしない。

**記入欄**

```
exported な Activity 一覧:
  1.
  2.
  3.

URLスキーム（あれば）:
  scheme:                host:

チャージ画面に直接遷移できる公開 Intent は存在したか:
  [ ] 存在した → Intent の内容:
  [ ] 存在しなかった → AccessibilityService による画面遷移へフォールバック
```

### 3.3 検証3 — AccessibilityService で ICOCA 画面のテキストが取れるか（§28-2）★最重要

**手順:**

1. 本アプリ設定 → 「自動操作について」の説明を読み、同意する
2. Android 設定 → ユーザー補助 → インストール済みアプリ → 「ICOCA自動チャージ支援」を ON
3. 本アプリ `Debug` タブ →「画面ダンプを記録」を ON にする
4. ICOCA アプリを開き、**残高が表示されているメイン画面**を数秒表示する
5. 本アプリに戻り、`Debug` タブ →「最後にダンプした画面」を確認する

**確認すべきこと（一つずつ判定する）:**

| 確認項目 | 結果 |
|---|---|
| ICOCA アプリを開いたとき `TYPE_WINDOW_STATE_CHANGED` を受信したか | ⬜ |
| `rootInActiveWindow` が `null` でないか | ⬜ |
| ノードが 1 個以上取得できたか（0個ならUI情報を出していない） | ⬜ |
| ノードに残高らしき数値のテキストが含まれるか | ⬜ |
| `viewIdResourceName` が意味のある名前か、難読化されているか | ⬜ |
| ICOCA アプリが「ユーザー補助が有効」を検知して警告や機能制限を出さないか | ⬜ |

**記入欄**

```
ダンプできたノード数     :
残高テキストの原文       : 例) "¥2,840" / "2,840円" / 取得不可
そのノードの viewId      :
そのノードの className   :
親ノード/兄弟に「残高」ラベルはあったか: [ ] あり  [ ] なし
ICOCAアプリ側の妨害      : [ ] なし  [ ] 警告表示  [ ] 機能停止  内容:

⇒ 判定: [ ] ✅ 残高取得可能  [ ] ⚠️ 条件付き  [ ] ❌ 不可能
```

> **❌ 不可能だった場合**: `BalanceSourceType.ACCESSIBILITY` を設定で無効にし、
> 手動入力（G）＋通知 Fallback（指示書 §27）で運用する。これは想定内の結果であり、アプリは成立する。

### 3.4 検証4 — チャージ画面への自動遷移（§28-4,5,6）

> **前提: 検証3 が ✅ か ⚠️ の場合のみ実施する。**

**手順:**

1. `Debug` タブ →「自動操作ドライラン」を ON にする
   （**ドライランではクリックを実行せず、「押す予定のノード」をログに出すだけ**）
2. 本アプリから「今すぐチャージ」を実行し、ICOCA アプリが起動するのを待つ
3. ICOCA アプリのチャージ画面まで**手動で**進み、各画面で `Debug` タブのログを確認する

**記入欄（画面ごと）**

```
[メイン画面]
  検知できたか        : [ ] はい [ ] いいえ
  「チャージ」ボタンのtext / contentDescription / viewId:

[チャージ画面]
  検知できたか        : [ ] はい [ ] いいえ
  金額ボタンの表現    : 例) text="5,000円" / "¥5,000" / contentDescription=
  5,000円ボタンのviewId:
  金額入力欄はあるか  : [ ] あり(editable) [ ] なし(固定ボタンのみ)

[決済確認画面]
  検知できたか        : [ ] はい [ ] いいえ
  画面を特定できるキーワード:

[3Dセキュア / 認証画面]
  検知できたか        : [ ] はい [ ] いいえ  ← ここは「検知して停止する」ことが正しい動作
  WebViewか           : [ ] はい [ ] いいえ

[完了画面]
  検知できたか        : [ ] はい [ ] いいえ
  画面を特定できるキーワード:
  完了後の残高表示    :
```

### 3.5 検証5 — NFC / FeliCa（§5-C）

**手順:**

1. `Debug` タブ →「NFC残高読み取り（物理カード）」を押す
2. **物理の ICOCA カード**を端末背面にかざす → 残高が読めるか確認
3. 次に **何もかざさずに**同じ操作をして、自端末のモバイルICOCA が読めないことを確認

**記入欄**

```
物理ICOCAカードの読み取り : [ ] 成功 (残高 ¥      ) [ ] 失敗 (理由:            )
自端末モバイルICOCAの読取 : [ ] 読めた(想定外) [ ] 読めない(想定どおり)
NFCアダプタの有無         : [ ] あり [ ] なし
```

### 3.6 検証6 — OMAPI（§5-F）

**手順:** `Debug` タブ →「OMAPI 調査」を押す

**記入欄**
