### 3.1 二重チャージ防止の重点検証（§21）

指示書が最重要とする項目。以下を個別に実施する。

| # | シナリオ | 期待 |
|---|---|---|
| A | 2,500円検知 → チャージ開始 → 処理中に監視が走り 2,500円を再観測 | **新しい attempt を作らない**。履歴が1件のまま |
| B | チャージ成功 → 残高 7,500 → 監視 | `ABOVE_THRESHOLD` で発火しない |
| C | チャージ後も残高表示が古く 2,500 のまま | `balanceAtDetection` 一致で発火しない |
| D | ユーザーがキャンセル → 5分後に監視 | クールダウンで発火しない |
| E | クールダウン 6 時間経過後に監視 | 発火する（1件だけ） |
| F | アプリを強制停止 → 再起動 → 監視 | 進行中 state が復元され、二重に発火しない |
| G | CHARGE_PENDING のまま 30 分放置 | `FAILED(TIMEOUT)` になり state が解放される |

## 4. 手動確認が必要な非機能項目

| 項目 | 確認方法 |
|---|---|
| バッテリー消費 | 設定 > バッテリー > アプリの使用状況。24時間で 1% 未満であること |
| 権限が最小か | 設定 > アプリ > 権限。`POST_NOTIFICATIONS` と NFC のみ（＋ユーザー補助は別枠） |
| ネットワークを使っていないこと | `INTERNET` 権限が無いことを `dumpsys package` で確認 |
| 履歴のバックアップ除外 | `adb shell bmgr` でバックアップ対象外であること |
